# Showroom update — 9 September 2026

This ZIP includes the complete application, the production build, an additive database migration, and a saved NHTSA vehicle catalog. Existing users, cars, transactions, and accounts are not replaced.

## Updating an existing installation

1. Back up your database and your existing application folder.
2. Stop the application while updating. Replace the application files, preserving your own `server/.env` and any uploaded photos. Do not copy a demo database over your data.
3. From the project folder, run:

```bash
npm ci
npm run db:migrate
npm run generate --workspace=server
npm run catalog:import
npm run build
npm start
```

For a process-manager installation, restart the existing process instead of starting a second one. The migration adds nullable repair-to-charge identifiers; it does not drop or truncate tables. Run the migration before starting the new application.

For a new installation, follow START-HERE.txt / `npm run setup`. The setup imports the saved catalog locally.

## Vehicle catalog

The bundled `server/prisma/vpic-catalog.json` contains 406 makes and 4,790 models downloaded from NHTSA vPIC on 9 September 2026. It combines the makes listed under cars, trucks, and multipurpose passenger vehicles (including SUVs), then fetches each make's model list. Some makes also produce other vehicle types. This is a make/model reference, not a complete model-year, trim, or body-style database.

NHTSA describes its coverage as vehicles intended for sale or import into the United States. It does not promise all vehicles worldwide. Keep manual entry for unlisted models. The API's own vehicle type classifications are not inferred or replaced here.

- Brand/model searches query MySQL only.
- Only VIN decoding calls NHTSA during normal application use. VIN entry can still be completed by hand when the service is unavailable.
- `npm run catalog:import` imports the saved snapshot once. Re-running it skips an already completed import.
- To refresh the database from NHTSA, explicitly run `npm run catalog:import -- --refresh`. Failed model downloads can be resumed by running the import again without `--refresh`. Refresh adds/updates reference data; it does not remove manually entered data or alter existing cars.
- To create a new downloadable snapshot, run `npm run catalog:download`. Interrupted downloads resume from a checkpoint; `-- --refresh` restarts the snapshot. The last complete snapshot remains intact if requests fail.
- Settings shows stored make/model counts and the import date.

Sources: https://vpic.nhtsa.dot.gov/ and https://vpic.nhtsa.dot.gov/api/

## Fixed

- Shipment removal verifies the car belongs to that shipment and is still eligible for removal. Sold/arrived cars cannot be reset to purchased.
- Freight allocations reject duplicate car IDs. Missing IDs are rejected when assigning cars, and newly added cars inherit an already-shipped load's status.
- Arrival validation, cost snapshots, freight charges, and audit records commit together. Concurrent requests are checked within serializable transactions and rolled-back conflicts are retried.
- Initial payments cannot exceed the price. Local sale amounts use whole CFA francs; origin sale prices preserve USD cents.
- Origin sales display as settled with the supplier and cannot accept additional customer payments. Existing payment history is retained.
- Concurrent instalments cannot exceed the remaining balance.
- New repair and part records store their exact ledger-charge ID. Removing the repair and reversing its charge commit together.
- Sold cars' repairs cannot be deleted. Extra origin expenses cannot be added after an origin sale. These guards preserve historical cost and profit.
- Recovery-code consumption uses an atomic unused-to-used update, preventing concurrent reuse.
- Duplicate-key errors work with MySQL's string-shaped constraint metadata.

## Older repair records

Older records have no exact charge ID. If there is exactly one matching repair and one unreversed charge, deletion can safely reconcile them. If multiple repairs/charges could match, deletion returns a clear conflict and changes nothing. Do not guess the mapping or delete charges manually. Reconciliation requires the original records. This update does not attempt to reconstruct damage from past bugs without evidence.

## Payment handling retained

Recording a customer payment reduces the sale balance and, if linked, the customer's account balance. It does not automatically credit the cash box or a transfer-company account. A deposit is still recorded separately. Automatic receipt posting needs a chosen destination account and should replace the separate deposit, to avoid counting the same money twice.

Post-sale adjustments are not introduced in this release. Sold repair costs are protected. A future adjustment flow can retain the original line and record an explicit correction with its reason.
