CAR SHOWROOM SYSTEM — START HERE
=================================

This is a clean install, from nothing. Follow it in order.
There are only two things to double-click.


1. INSTALL THESE TWO PROGRAMS
-----------------------------
1. Node.js (LTS)   https://nodejs.org
2. Docker Desktop  https://www.docker.com/products/docker-desktop/
   - Tick "Use WSL 2", restart your PC when asked
   - Open Docker Desktop and wait for the whale icon to turn GREEN

   (No Docker? Install MySQL instead:
    https://dev.mysql.com/downloads/installer/ -> "Server only")

After installing Node, CLOSE PowerShell and OPEN IT AGAIN,
or it will not find the new commands.


2. PUT THE FOLDER SOMEWHERE
---------------------------
Extract the zip. Inside it is one folder called "showroom".
Put it wherever you like - the Desktop is fine.

Open that folder. You should see setup.cmd, start.cmd,
doctor.cmd, package.json, and folders called server, web
and docs.

If instead you see another folder called "showroom", open it:
the zip was extracted one level deeper than you wanted.


3. SET IT UP
------------
Double-click:

    setup.cmd

That is the whole setup. It starts a database, installs
everything, builds the tables, loads the car brand list and
loads the practice showroom. It takes a few minutes and asks
you nothing.

Do not open PowerShell first. Double-clicking is what makes
this reliable: the file moves to its own folder before doing
anything, so it cannot run in the wrong place - which is what
goes wrong when commands are typed by hand.

If a window flashes open and shuts, run it from PowerShell so
the message stays on screen:

    cd "<the folder you extracted>"
    .\setup.cmd


4. START IT
-----------
Double-click:

    start.cmd

Then open your browser at:   http://localhost:5173

    username:  owner
    password:  Showroom-Test-2026

Press Ctrl+C in the black window to stop it.


IF YOU PREFER TO TYPE THE COMMANDS
----------------------------------
Everything setup.cmd does, by hand. Open PowerShell IN the
folder: hold Shift, right-click an empty part of the folder
window, and choose "Open PowerShell window here". That way the
path is right without typing it.

    docker run --name showroom-db -e MYSQL_ROOT_PASSWORD=devpassword -p 3307:3306 -d mysql:8
    npm ci
    npm run setup -- --big --db "mysql://root:devpassword@127.0.0.1:3307/carshowroom"
    npm run dev

Port 3307 is used on purpose: 3306 is usually already taken by
another MySQL, and that clash is hard to spot later.

Already have a container called showroom-db from an earlier
attempt? Delete it first, so its old password cannot come back
to haunt you:

    docker rm -f showroom-db

Starting completely over later (ERASES EVERYTHING):

    npm run setup -- --big --fresh --db "mysql://root:devpassword@127.0.0.1:3307/carshowroom"


NEXT TIME YOU WANT TO USE IT
----------------------------
1. Open Docker Desktop, wait for the green whale
2. Double-click start.cmd


WHAT YOU WILL SEE
-----------------
70 cars: 50 for sale, 6 being repaired, 14 already sold.
5 suppliers (3 American, 2 Canadian), 5 shipping companies,
5 money transfer companies, 3 cars held with a deposit.

Every practice chassis number starts with TEST5, so practice
cars can never be mistaken for real ones.

Worth trying first:

- Garage: each car sits under the trade it is waiting for.
  Open one, tick a trade, and list the parts it needs — a part
  with no price yet puts a warning mark on its card, and no
  supplier is charged until you record the part as bought.

- Showroom: a car whose cost has passed its asking price shows
  a red warning at the top. Click it to go straight to the car
  and change the price.

- Reports -> any month: gross profit, then overhead, then what
  you actually made.

When you are ready to enter your own cars, clear the practice
data first:

    npm run db:seed:large -- --wipe


CAR BRAND LIST
--------------
The brand and model list comes from a free US government
service (NHTSA vPIC). No signup, no key needed.

"npm run setup" already tried to load it. If your internet
was working you have the full list already.

If it said "Could not reach NHTSA vPIC", it used a smaller
bundled list of 35 brands so you were not blocked. To load
the full one later:

    npm run db:seed:vpic

That takes a few minutes. Run it again any time - it only
adds what is missing and never touches your cars.

IF SOMETHING GOES WRONG
-----------------------
FIRST: double-click doctor.cmd

It checks everything that can be wrong - the database, the
tables, how many cars, which logins exist, whether two-factor
is on, whether the system is running - and prints what to do
about each thing it finds. It only reads; it changes nothing.
If you are asking someone for help, send them what it prints.

Then, by symptom:

"Could not reach MySQL"
    Docker Desktop is not running, or the database is stopped.
    Open Docker Desktop, then:  docker start showroom-db

"'npm' is not recognized"
    Node.js is not installed, or you did not reopen PowerShell.

"Could not read package.json ... C:\Users\<you>\package.json"
    The command ran in the wrong folder. This is what setup.cmd
    and start.cmd exist to prevent - double-click those instead
    of typing. (A "cd" that fails leaves you where you were, and
    everything after it runs in the wrong place.)

"ports are not available ... 3306"
    Something else is already using that port. The instructions
    above use 3307 to avoid it.

"http proxy error ... ECONNREFUSED 127.0.0.1:4000"
    The screens are running but the part holding your data is
    not. Run the two halves in separate PowerShell windows so
    the real error is not buried:
        npm run dev:api
        npm run dev:web

"Could not build the code's picture of the database"
    The application is running and Windows will not replace its
    files while they are open. Press Ctrl+C where "npm run dev"
    is running, then try again.

It asks for a code from your authenticator app
    Two-factor is switched on for that login. A fresh install never has
    it on, and setting the password from the console switches it off,
    so this only happens on a database where somebody turned it on in
    Settings. Either set a new password:
        npm run create:user -- owner "a-password-12-chars+"
    or keep the password you have and just switch two-factor off:
        npm run reset:2fa -- owner

Anything else: the PowerShell window prints the real reason.
That message is what to go on.
