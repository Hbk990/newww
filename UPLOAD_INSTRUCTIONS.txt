DR PHONE WHOLESALE — HARDENED INSTALLATION (v15)

READ THIS FIRST — WHICH ROUTE TO TAKE
This ZIP is a complete install and it contains a copy of the catalog data as
it stood when the package was built. Two situations:

  A) You have added, edited or deleted products through the dashboard, or you
     have customer orders in the order log, since your last install.
     -> Do NOT do a full replace. Upload only these files over the top,
        keeping everything else on the server exactly as it is:
          wholesale-.../assets/styles.css
          wholesale-.../assets/catalog.js
          wholesale-.../assets/admin-extra.css
          wholesale-.../assets/admin.js
          wholesale-.../index.php
          wholesale-.../admin/index.php
          wholesale-.../admin/api.php
          wholesale-.../api/order.php
          wholesale-.../api/order-status.php   (new file)
          wholesale-.../inc/bootstrap.php
          wholesale-.../.htaccess
        Then DELETE wholesale-.../assets/opencv.js from the server: it is
        10.9 MB, nothing uses it any more, and it never worked.
        That upgrades the software and leaves your data alone. Nothing else in
        this package has changed.

  B) It is a fresh server, or you have made no changes since the last install.
     -> Follow the full steps below.

A full replace overwrites storage/catalog.json with the copy in this ZIP, and
removing the old folder first also deletes storage/orders.json, which is where
your order history lives. Download the whole storage folder before you start,
whichever route you take.

FULL INSTALL

1. Open Hostinger File Manager and enter public_html.
2. Back up the old catalog — download the entire storage folder, including
   orders.json — then remove its old root folders and files from public_html.
   Do not remove unrelated email or Hostinger system files.
3. Upload this ZIP directly into public_html.
4. Extract it there. Keep the private folder name unchanged.
5. Delete the ZIP from the server after extraction.
6. Customer catalog URL:
   https://drphonewholesale.online/wholesale-7nQ4vK9mP2xR8cL5/
7. Admin URL:
   https://drphonewholesale.online/wholesale-7nQ4vK9mP2xR8cL5/admin/
8. Confirm that https://drphonewholesale.online shows only a generic 404 page.
9. Confirm that the customer passcode is required before the catalog opens.

IMPORTANT
- Do not rename or publicly post the private catalog folder.
- Send customers the complete catalog URL, not only the domain.
- Keep the customer passcode enabled and change it if the link is leaked.
- Do not submit a sitemap for this website.
- Do not add the catalog URL to public social-media profiles or public websites.
- The no-index protection prevents search indexing but is not a replacement for the passcode.

BULK PRODUCT PICTURES
- Import the product CSV first so every product code/SKU already exists.
- In Admin Dashboard > Operations, use "Bulk product pictures".
- Name each main picture exactly as its SKU: DR-00001.jpg
- Add gallery pictures with a number: DR-00001-2.jpg, DR-00001-3.webp
- SKU matching is case-insensitive. Only JPG, PNG and WEBP are accepted (maximum 5 MB each).
- Your host may limit one selection to 20 files. If so, upload the pictures in batches.
- The dashboard reports filenames that do not match any SKU; it never guesses a product.
- New images are resized to a maximum of 1400 px and compressed to WEBP quality 82 when Hostinger GD/WebP support is enabled.
- Replaced main pictures are removed automatically when no product still uses them.
- "Delete unused pictures" removes orphan files not used by the current catalog. Data backups do not contain image copies.
- The server retains the latest 10 catalog/settings backups and automatically removes older ones.

VISUAL PRODUCT VARIATIONS
- Product options, colors, flavors, availability and per-variation quantities are managed only through visual Add/Edit/Delete controls.
- The obsolete manual option/color/flavor/stock-override textareas have been removed from the dashboard.

WHAT IS NEW IN v14
Customer catalog
- Quantity price breaks are now shown on the product. The cart has always
  applied them; nothing used to tell the customer they existed. Each product
  lists its breaks, the one reached is highlighted, and a line says how many
  more pieces reach the next price. A break the stock cannot cover is never
  advertised.
- "Order pad" view: the same products as compact rows instead of picture
  cards, about six times as many per screen, for buyers who already know what
  they want. The choice is remembered per device. Switch with Cards / Order pad
  next to Sort.
- Filters for brand, in-stock only and a price range.

Dashboard
- New "Sales" tab built from the order log: orders, pieces, revenue and average
  order value; order value per day; most ordered products; categories by
  revenue; and a 7 / 30 / 90 day / all-time range picker.
- "What to reorder": stock on hand against how fast each product actually sold,
  showing what runs out first and roughly when. Products that sold but have no
  stock quantity recorded are listed separately — they cannot be given a
  reorder date until a quantity is entered, and the best sellers among them are
  named so you know which to count first.
- Selecting a whole category with its checkbox can now be undone by clicking it
  again, and shows a dash when only some of its products are selected.

Mobile
- Every input is 16px on touch, so iOS no longer zooms the page when a customer
  taps a quantity box.
- Every button and tappable row is at least 44x44.
- The quantity field scrolls clear of the on-screen keyboard while typing.
- Below 375px the header is two tidy rows instead of three ragged ones.
- Below 361px the product grid is one card per row; two-up left too little
  space for a usable quantity control.

WHAT IS NEW IN v15
Cancelled and never-sent orders
- An order is recorded the moment a customer taps WhatsApp, which is before the
  message is even written. WhatsApp tells this site nothing, so the site cannot
  know whether it was sent, deleted or cancelled afterwards.
- Orders therefore start as UNCONFIRMED, and either side can settle them: the
  customer is asked "Did you send order DR-...?" when they come back to the
  catalog, and the Order log has Confirm / Cancel / Restore on every order plus
  a status filter.
- The Sales tab and "What to reorder" count CONFIRMED orders only, so phantom
  orders can no longer inflate your revenue or overstate how fast stock moves.
  The value of anything still waiting is shown above the figures, so nothing is
  hidden from you.
- Cancelling keeps the record (struck through) instead of deleting it, so you
  can still see what was cancelled. Delete is still there for genuine rubbish.
- Orders recorded before this version keep counting; they are treated as
  confirmed rather than being wiped from your history.
- In the Order log, the "Items" button now actually hides and shows the items.
  It never did before.

REMOVED IN v15
- The OpenCV image audit has been removed. It could never run: the library
  builds its own code from text at startup, which the catalog's security policy
  forbids, so it always failed after 60 seconds with a message that wrongly
  blamed the upload. Removing it also deletes a 10.9 MB file: the installed
  folder drops from 28.3 MB to 17.3 MB, and this ZIP from 20 MB to 16 MB (the
  file compressed well, so the download shrinks less than the install does).
- The "Image quality audit" in Operations is a different, server-side check and
  still works; it reports missing and low-resolution pictures.
- If storage/opencv-image-audit.json exists on the server, delete it. Nothing
  reads it any more.

NOTE ON PRICE TIERS
A single cart line is capped at 999 pieces, so a tier whose minimum quantity is
1000 or more can never be reached and will never apply. Keep tier minimums
below 1000.
